# Luna implementation quality gates

Read this before changing a task card's implementation. Read [12_CURRENT_STATUS.md](12_CURRENT_STATUS.md) to find the next unfinished gate. The chronological implementation log is evidence history, not a current completion table.

These checks address the failures found in the 4 October audit. They reduce recurrence; they do not guarantee defect-free code. Apply the checks relevant to the changed behavior rather than rerunning expensive GPU work for every code edit.

## Prove the consumer journey
For generated dialogue acceptance, extract audio from the hash-verified registered output and perform local timestamped ASR before requesting human listening. Save unbiased full-clip and relevant segment transcripts, model/device and source hash. Extra/uncertain speech is a hold, not an approval; a correct required line does not excuse a garbled opening. Preserve native audio and prior attempts. Use CPU/cached models where available, and never treat an ASR transcript alone as proof of voice identity or absence of unwanted speech.

For chunked story expansion, ask the provider for exact source quotations, not character offsets. Derive offsets server-side from each exact quote, persist the resulting source slice, and reject empty or absent quotations. Never trust a model-calculated span. Regressions must include invalid provider indices with a valid quote and verify the canonical persisted slice after API restart; a completed task alone does not open the Full-mode gate if Director review or downstream scene acceptance remains pending.


For each changed contract, name its producer, durable representation and consumer. A field written by one stage must be the field read by the next stage. Use a test crossing those boundaries with the real local persistence implementation.

For Director dialogue and shot planning, bind one accepted dialogue unit to each stable planned `shot_id`; require exact set equality (no missing, extra or duplicate IDs) and the matching `scene_id`. Persist the accepted lines under that shot, pass them into its shot-plan request, and enforce those exact `speaker_id` and text values in the saved shot plan. Do not align scene-level dialogue beats by array order or ask the shot-plan provider to reconstruct lines from a revision ID alone. Regressions must cover empty-dialogue shots, missing/extra/duplicate IDs, cross-scene links, and provider omission or mutation of accepted lines. A CPU fixture is not live configured-provider acceptance.

For dialogue generation, construct the stable character-ID-to-canonical-name map from active project canon for the exact IDs allowed on each shot, pass the same map to both generator and Director reviewer, and fail closed if any referenced ID has no active name. Do not infer identity from array order or role labels. Dialogue output may contain only `content.dialogue`; reject unrelated fields before Director review so a dialogue candidate cannot be rejected for shot/action metadata owned by another stage. Regressions must cover map propagation to both consumers, unresolved IDs, extra content fields, and an accepted non-empty configured-provider case. Keep prompt contract tests semantic and aligned with the actual concise prompt; test output validation separately so wording edits do not mask contract regressions.

An implementation slice is not an integrated capability merely because its modules pass isolated unit tests. For every new delegated workflow, prove the vertical path from saved run configuration and API request, through real local queue persistence and worker dispatch, to canonical output/decision record, status API, and the browser state that consumes it. Assert both the success path and restart/replay path. If a required callback, adapter, controller, or UI consumer is absent, keep the capability gate closed and test the explicit unavailable response. Do not remove an existing 409/disabled gate until the vertical test demonstrates the whole path.

For UI state shared by an editable composer and durable take review, test selecting a saved take from both the same shot and a different shot, including when a validated preview already exists. Composer reset effects must not erase the explicitly selected durable take. The candidate's canonical media and one authoritative set of review actions must remain visible; assert these through a browser test backed by registered output metadata, not only a mocked badge. Keep the render preview available when the selected take belongs to that same shot so a user can retry without silently losing validated inputs.

- Image approval: register a real temporary PNG candidate, accept it, assign its canon identity, then pass it through route validation. Assert that an unaccepted candidate, a false client role, a duplicate asset, and a wrong/missing identity are rejected. Do not mock the registry response to invent approval or private storage fields.

Add forged-role, cross-run, wrong-master/hash and missing-binding regressions; keep the existing 409 gates closed until Director take creation requires the exact accepted preparation task and the complete automatic queue→worker→review/replay→browser journey passes.
- For Director-owned H3 output review, resolve the video only by its canonical asset ID from the real registry. Probe duration and extract a fixed, bounded set of representative frames; analyze them CPU-only and pass their descriptions as untrusted evidence to the run-pinned provider. ## Test writes and ambiguous submission outcomes

Atomic rename prevents torn JSON, not lost concurrent updates. Manifest mutations must lock the complete read/modify/write transaction across processes. A concurrency regression must verify that every successful registration remains retrievable, including concurrent approval/registration when those paths change.

Before a ComfyUI POST, persist a reserved prompt ID in the owning durable job. Test a lost POST reply and a backend exit after reservation/submission. The job retains the exact prompt and becomes `recovery_required` when remote state is unknown. Recovery observes that ID; it never silently posts a replacement. Idempotency keys are scoped to project/run and conflict on different inputs. Browser retries after an unknown response retain the same key.

Production audio uses `production_audio_sidecars.py` as its authoritative SQLite queue. Background execution is only a wake-up; the startup consumer and per-job ownership lock provide recovery and prevent simultaneous execution. Test both the store and API/consumer boundary. A persistence exception must prevent submission, not be logged and ignored.

For generated dialogue TTS, discriminate the operation kind at each layer: request validation, durable queue row, startup/worker dispatch, ComfyUI graph, canonical asset registration, status response, and browser playback. Do not route spoken lines through the music/SFX graph or replace legacy ChatterBox conversion. Bind every submitted speaker to an active character, the saved run voice binding, and an accepted excerpt whose run, character, source-master ID, duration and bytes/hash are verified from the real asset registry. Assert the exact supplied line text and speaker order reach the SRT, intervals are finite, ordered and non-overlapping, and staged references are owned by the job. Reserve and persist one prompt ID before submission; test lost replies, backend restart/replay, ambiguous remote state, and idempotency conflicts without posting a replacement. The browser test must submit exact two-character dialogue, observe terminal job status, and consume the canonical registered audio URL. A mocked browser result proves UI wiring only; it does not prove generated speech quality or that the installed node graph produces playable audio. Keep the live acceptance gate open until a disposable two-character render is played/listened to and checked for both speakers, exact words, duration, output registration, prompt reconciliation, cleanup and post-job model release.

Before submitting any model-backed graph, validate model/checkpoint/tokenizer readiness on the actual ComfyUI host and expected paths; `/object_info` proves node schema only, not that the model can run without fetching weights. Default to offline/local-only readiness checks. If required files are absent, stop before reserving/submitting a GPU prompt and report the missing files. Do not silently permit a node to download model weights during supervised inference. ComfyUI's global `/interrupt` is cooperative: acknowledgment does not prove the current node stopped. Model loaders and downloads may remain uninterruptible until a later node boundary, and inference may start before the interrupt is observed. For any approved live run, monitor through exact prompt terminal state and temperature continuously; never equate an interrupt request with cancellation completion.

For cancellation, delete only the exact known prompt while it is pending. For a running prompt, re-read `/queue` through `interrupt_if_owned_prompt` and request ComfyUI's global `/interrupt` only when the target prompt is the sole running item and the pending queue is empty. If ownership cannot be proven, persist `cancel_requested`, retain staging and reconcile the exact prompt; do not broaden the interrupt. Every accepted API cancellation state must also be legal in the durable ledger state machine, including `recovery_required → cancel_requested`. Tests should cover an owned running prompt, a changed/foreign queue refusal, a prompt absent from queue, ambiguous ComfyUI health and repeated cancellation; interrupt acknowledgment never itself means `cancelled`.

For a `recovery_required` video take, retain the reserved prompt ID and keep retry disabled until an explicit operator action calls a server-side exact-prompt reconciliation. The API must check that the supplied ID matches the take, the ID is absent from both ComfyUI queue lists and its history, and the ledger has no registered outputs. Queue/history errors or malformed responses are uncertainty and must leave the take unchanged. Only after the operator confirms no usable output may the API atomically compare-and-set the same `recovery_required` row, run and prompt ID to `failed`; the transaction must reject a worker state change or newly registered output. Record the observations and confirmation in the event/error evidence. Do not stop, interrupt, release, or resubmit a prompt during this reconciliation. Retry remains a separate user action through the normal monitored worker. Test queued/running, history present, service unavailable, malformed response, prompt mismatch, missing confirmation, registered output, and the final SQLite race. The browser must show the reserved ID, require a scoped confirmation, display busy/error/success state, and expose retry only after successful resolution.

## Supervise live render work independently

All ComfyUI submissions use the shared admission lock and host checks. Video/image/audio prompt owners start or recover `gpu_watchdog.py` for the exact reserved prompt. Its detached process samples temperature/clock independently of slow HTTP polling and backend lifetime. It interrupts only if `/queue` proves that exact prompt is the sole running item with no pending item. Preserve unknown state and the ownership refusal; do not terminate unrelated GPU processes.

Separate **admission** resources from **in-flight** supervision. Enforce the minimum-free-memory reserve before submission only. After the saved prompt is running, that prompt's model allocations may consume the reserve; do not mark the owned render unrecoverable solely because free memory fell below the pre-submit threshold. Continue checking temperature, graphics clock, exact prompt/queue ownership, compute-process ownership, and driver errors. Record in-flight memory for diagnosis. When the queue becomes idle, request model release through the guarded helper and verify that memory/headroom actually recovered before admitting the next job. Test low free memory at both boundaries: reject before submission; preserve active monitoring for the one owned prompt; continue to reject foreign processes/prompts and temperature/clock violations.

Current operator policy: maximum requested temperature 85°C, intervention cutoff 83°C, graphics-clock ceiling 2100 MHz. The user reapplies `sudo nvidia-smi --lock-gpu-clocks=300,2200` after each power cycle; verify observed clocks during admission. The NVIDIA clock cap is an operator setting, not a setting the application silently changes. Sampling/interrupt latency and ComfyUI's global interrupt API mean this is not a guarantee that hardware cannot reach 85°C. Direct analyzer process/container cancellation has separate ownership checks and CPU regressions; live container cancellation acceptance still requires healthy GPU/service telemetry.

Direct CUDA/analyzer cancellation has its own ownership contract. Every Docker container launched for a Story Builder analysis must carry the durable analysis job ID as a label. Cancellation queries and stops only containers returned for that exact label, verifies that none remain, and leaves the job in `cancel_requested` when Docker is unavailable or verification fails. Before signaling a worker process group, prove the persisted PID is the session leader and its `/proc/<pid>/cmdline` names the exact worker kind and job ID. Scan/stop the exact job label again after the worker exits, closing the race where it launches a new stage just after the initial scan. Do not mark cancellation complete until both the exact labeled containers and owned worker have exited. Worker progress/failure writes must not overwrite `cancel_requested`. Tests must use a fake Docker executable/container listing and a real sleeping fixture worker; they must prove foreign containers/processes are untouched and uncertainty preserves the pending state. Never stop unrelated GPU processes to make a test pass.

Unit tests inject synthetic GPU readers and HTTP responses. Include blocked-HTTP sampling, telemetry failure, exceeded temperature/clock, foreign prompt refusal, and detached process survival tests when changing supervision. The process test uses a fake `nvidia-smi`, never the physical GPU. Keep host stubs scoped to state-machine tests; never globally stub the GPU-policy tests or suppress a failed test.

## Periodic review and recovery requirements

A prompt in either running or pending queue remains owned and must not be classified absent. A failed or malformed queue response is uncertainty and must preserve the current durable state. Repeated identical observations must be idempotent: do not append a reconciliation event or update the durable row timestamp unless the observed state actually changes. When no take/review work is active, the supervisor must back off even if it inspected a recovery candidate. Add regressions for queued prompts, malformed/unavailable queue responses, repeated absent observations, and supervisor backoff. Do not clean up large historical ledgers or WAL files in a feature fix; plan and back up any maintenance separately.

Run-detail reads must not load unbounded audit history into memory or serialize it into every status response. Return a bounded newest-event window in chronological order and expose an explicit truncation indicator; keep full history in SQLite for audit/maintenance. Add persistence tests proving recent-window ordering, truncation, and full retrieval below the limit.

Test an accepted replacement after one/two retakes as well as unresolved/conflicting histories; blocking every multi-take shot is not a working retake implementation.

Keep the original task-card scope fixed. Use the review's bounded remaining packages, reuse recorded baseline proof, and combine compatible live acceptance checks. A changed/missing/stale draft or any Semi/Full child remains `waiting_for_user`. ## Controller-generated text unit bounds and identity evidence

- Any controller stage that reuses a verbose upstream revision must construct stage-specific input. Preserve the semantic fields the stage consumes; omit unrelated prose and enforce a stable serialized-size ceiling below the effective chunk budget.
