# Backend routing, durable jobs, runtime boundaries and launcher

Build this **additively** around `api/main.py`, `services/project_store.py`, `services/media_jobs.py`, `services/reasoning_provider.py` and current ComfyUI. The new shot path must not call the fixture-based `services/production_runner.py`. Do not let the front end call ComfyUI directly; the backend validates inputs, owns the graph/job, and returns safe URLs and typed errors.

## API shape (proposed; verify collision and naming in `api/main.py` before coding)

Preserve existing `/api/projects/*`, `/api/projects/{id}/automation/*`, `/api/projects/{id}/production/start|run`, `/api/media/*`, `/api/video-repertoire/*`, and all Manual Director routes. New project production endpoints can use `/api/projects/{project_id}/production/v2/...` until replacement is accepted:

| Endpoint | Purpose and validation |
|---|---|
| `POST /production/v2/runs` | Require non-empty project story; snapshot control mode, making route, four Semi gates, provider/model, style/version, H3 rules version, audio/consent policy and feature capabilities. Return run ID/status. Do not launch the old fixture runner. |
| `GET /production/v2/runs/{run_id}` | Durable stage/shot/job state, current revision, pending human decisions, progress and recoverable failures. Polling or SSE can be added behind same state contract; do not require a persistent browser connection. |
| `PATCH /production/v2/runs/{run_id}` | At safe boundaries update mode/route/gates; return affected-shot invalidation preview. Never silently change an in-flight GPU job's inputs. |
| `POST /production/v2/runs/{run_id}/story/detail` and scoped artifact/revision actions | Director expansion/chunked generation of mandatory story, scenes, dialogue and shot plans; support user edits and approved revisions. Reuse old artifact shapes and style catalog. |
| `GET /production/v2/workflows` | Live/last-known capability catalog: exact image/H3 workflow IDs, model/checkpoint/node readiness, accepted slots, settings, limits, disabled reason and graph compiler version. |
| `GET /production/v2/assets` and `POST /production/v2/assets` | Project-scoped indexed assets/uploads with pagination/filter/category; validate type, size, probe, hash, owner and safe path. Link external Video Repertoire IDs without copying. |
| `POST /production/v2/assets/{asset_id}/generate|accept` | Create image/audio candidates and accept one; retain versioned prompt/model/seed provenance and optional source image intents. |
| `GET/PATCH /production/v2/shots/{shot_id}` | ShotPlan and revisions: story facts, world/character IDs, voices, timing, prompt, intents, workflow family, reference selections, previous-shot dependency and output policy. Require `If-Match`/revision or equivalent optimistic concurrency for edits. |
| `POST /production/v2/shots/{shot_id}/refine` | Provider-generated **proposal** only: main prompt diff/rationale/warnings for H3, or image-model prompt diff for asset generation. Never submit media or alter selected asset IDs. |
| `POST /production/v2/shots/{shot_id}/validate` | Resolve assets, compile dynamic graph, return exact `<Picture>/<Video>/<Audio>` map, limits and typed warnings/errors; GPU-free. Persist a validation token/hash bound to plan revision. |
| `POST /production/v2/shots/{shot_id}/takes` | Idempotently queue approved validated shot plan; return take/job ID and dependency. If previous cut is not accepted, state is `waiting_for_predecessor`, not already running. |
| `POST /production/v2/shots/{shot_id}/takes/{take_id}/accept` | Mark actual playable output accepted, bind next-cut dependency and revalidate waiting jobs. |
| `POST /production/v2/jobs/{job_id}/cancel|retry` | Cancel only this project's owned queued/running work; preserve diagnosis and accepted assets. Avoid broad ComfyUI queue clears. |
| `GET /production/v2/jobs/{job_id}` and media content routes | Progress, stage, errors, prompt ID, safe output URLs and correct MIME/range playback; resolve paths under allowlisted roots. |

Exact DTOs should be in Pydantic and matching TypeScript types. Error bodies need `code`, `message`, `stage`, `asset_id` or `node_id` when relevant, `retryable`, `correlation_id`, and safe `details`; do not return internal stack traces or credentials. Reuse current `video_repertoire` search/audio list via service calls, not a second copied data store. All write endpoints validate project ID/run/shot ownership and prevent path traversal; review the existing broad `/api/projects/{id}/files/{relative_path:path}` before extending it to new files.

## Durable run/job ledger

Create a small project-aware SQLite ledger (or equivalent transactionally durable store), leaving existing project JSON as compatibility/read model. Minimum tables/records: run, stage task, shot revision, asset, dependency, media job/take, prompt revision, event/audit. Every task has stable IDs, input revision hashes, owner project, status, start/end times, attempt number, lease/heartbeat, ComfyUI `prompt_id` when submitted, output hashes and structured error. Media files themselves are **not** stored in SQLite. Atomic transitions prevent two backend workers or a user double-click from submitting the same take twice.

State machine:

```text
draft → validated → queued
                 ├→ waiting_for_predecessor → queued (after accepted parent + same frozen inputs)
                 ├→ waiting_for_user (stale plan, unresolved asset, manual gate)
                 └→ running → collecting → needs_review → accepted
                                       └→ failed / cancelled / retrying
```

The single **Generate & Next** click saves the exact shot draft, validation token/hash and idempotency key, then returns quickly with a job ID. The browser may navigate immediately. A dependent job is queued but **not submitted** until its parent take is accepted; if parent changes, mark child stale and require revalidation. For Manual, the click is advance authorization: if the child draft remains unchanged, auto-submit after parent acceptance (user's decision); otherwise wait for review. For Full, the Director can accept/retake according to a recorded policy, never unboundedly. For Semi, each enabled gate pauses at the precise decision page. A crashed backend restarts, reconciles leases with ComfyUI history, and resumes incomplete stages without duplicating already accepted ComfyUI prompts.

Retakes create new `take_id` and do not overwrite prior output. An accepted earlier-shot retake prompts a dependency invalidation preview: queued children become stale; already accepted later videos remain intact until the user approves re-render/fork. Never rewrite a child prompt silently to point at a different parent take. Cancel a queued job locally; for submitted ComfyUI work, cancel **only its known prompt ID** where the API supports it, mark cancellation requested, reconcile eventual output and safely clean only owned temporary staging. Do not interpret a button press as proof the GPU operation stopped.

## Worker/resource design

Use background worker/subprocesses instead of blocking the FastAPI request until an H3 render completes. One project may prepare many shots while **GPU-heavy H3 jobs are strictly serialized**. Image/edit, TTS, H3 and analyzer jobs share a GPU; do not start them all simply because the browser queued them. The user's operational rule is one GPU-heavy inference/generation process at a time, globally—not merely one Story Builder job at a time. The website's durable queue is authoritative for website requests; all waiting work stays in that backend queue, while ComfyUI must have at most one running prompt and zero pending prompts. Record queue positions and estimated memory/time from completed benchmarks.

Before any live GPU submission, perform a fresh read-only preflight: (1) `nvidia-smi` and `nvidia-smi --query-compute-apps=pid,used_memory,process_name --format=csv,noheader` must succeed; (2) ComfyUI `/system_stats` and `/queue` must respond, with the queue empty and a safe free-memory margin; and (3) identify every compute PID. Display-only `G` processes are not inference jobs. The idle ComfyUI server process is expected, but any other GPU compute process (for example another Python model worker or Ollama inference) means **do not submit**; do not kill or unload a process owned by another app/session. If process ownership cannot be determined, telemetry disagrees, or NVIDIA/ComfyUI health is unavailable, fail closed and ask the operator to resolve/confirm before rendering. A 0% utilization reading alone is not proof that another model has released its allocation.

Run one generation, poll its exact job/prompt to a terminal state, then verify ComfyUI has returned to zero running/pending prompts and request model release only through the existing safe idle path. Confirm unload/cache-free status and recheck compute PIDs/utilization/free memory before starting the next queued item. Image, voice/TTS, video, and analyzer GPU work all use this same admission policy; concurrency across separate workers/containers is not allowed. Do not broad-clear ComfyUI's queue or lower quality/drop refs to fit memory without explicit approval. If a job is active, all subsequent work remains queued in Story Builder's backend; never enqueue a backlog in ComfyUI.

**Cross-page queue boundary:** all current Story Builder Comfy submitters must use the shared `services.media_jobs.comfy_submission_guard` (cross-thread/process admission lock), enforce the global single-GPU-workload policy above, and verify ComfyUI `/queue` is empty before posting. `submit_and_wait` holds this guard through completion; Production V2 takes are durably queued in the production ledger and recheck under the same guard before `/prompt`. This prevents overlapping website submissions and avoids filling ComfyUI's pending queue with concurrent site jobs. Legacy feature jobs still do not share one durable global queue/queue-position API, so their feature-level job records and backend waiters remain a future consolidation opportunity; they must not bypass the guard. Manually submitted ComfyUI work is external and cannot be prevented from arriving after an idle snapshot; if any prompt or foreign compute process appears while a production take is preparing, the take stays in the website backend queue. Never stop another client/session's job to make room.

The file lock is an **application-level coordinator**, not an operating-system reservation of the GB10. It serializes Story Builder code paths that acquire it and waits for ComfyUI work visible at the queue check; it cannot stop another repository, arbitrary CUDA process, desktop client, or a manual ComfyUI submission racing after that check. The human read-only `nvidia-smi` compute-PID preflight above remains mandatory before each live GPU acceptance/render. If another or unidentifiable compute PID is present, do not submit; wait for its owner or ask the operator. Do not describe this code as guaranteeing host-wide single-process GPU use.

Keep all node/loader/model assumptions behind the live capability registry. If an optional adapter is unavailable, disable its control but keep already tested T2V, image-only R2V, and other website routes functional. No ComfyUI package, Conda environment or Docker mutation as a normal step of this plan. A real dependency conflict requires a separate compatibility experiment and documented rollback, not a blanket update. Advanced Add Guide and Fun ControlNet are later independent plans/gates.

## Existing launcher and possible surgical changes

`run_story_builder.sh` already: checks Ollama `/api/tags`; starts it only if offline; checks ComfyUI `/system_stats`; calls the configured start script only if offline; starts backend `python3 -m uvicorn` and Vite. **Do not replace those checks or restart running services.** If the new production worker needs startup registration, add only a small health/preflight link to the same backend or a clearly named separate process with its own PID, log and cleanup behavior. Prefer starting durable worker logic from the backend/service supervisor once rather than duplicating the job consumer for every launcher call.

Before launch, preflight that the chosen Python has `uvicorn`/required modules and that requested backend/frontend ports are free **or explicitly fail with PID/port advice**. Vite should not silently move 8082→8083 while the script announces 8082; use strict-port behavior after confirming the installed Vite option. Print the actual URLs and service states. Keep current port env vars and `COMFYUI_URL` configurable; do not assume `base` Conda works when `react` did in prior tests. Do not install into `react` or `blender311` merely to fix a launcher message without comparing installed versions and testing existing pages. Codex-only new story generation should not cause removal of Ollama startup unless unrelated Ollama-backed pages are migrated/tested or an explicit optional-skip mode is chosen.

Log `run_id`, `shot_id`, `take_id`, `asset_id`, `workflow_version`, `prompt_id`, `stage`, elapsed time and bounded error details. Use human-readable messages *and* machine-readable reason codes (missing_model, wrong_media_type, invalid_reference_map, provider_unavailable, model_oom, output_missing, etc.). Redact secrets and avoid dumping whole story/audio payloads. On OOM/driver error, report GPU state, preserve compiled graph/attempt manifest, release only idle Story Builder-owned resources, and do not silently lower resolution or drop refs; ask for a new explicit attempt/policy.

**Runtime gate:** restart the backend with one queued child and one accepted parent and prove no duplicate ComfyUI submission; test port conflict startup; prove no duplicate Ollama/ComfyUI launch; complete a job with idle-model release attempted only when ComfyUI queue is empty; verify all old non-production pages still function.
